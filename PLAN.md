# Property Management System — Development Plan

A web app for landlords to register properties, track income/expenses, manage tenants & leases, and handle maintenance requests.

## Recommended Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | Next.js 15 (App Router) + React 19 | SSR, Server Actions, API routes in one |
| Language | TypeScript | Safety across the stack |
| UI | Tailwind CSS + shadcn/ui | Fast, accessible, consistent components |
| Database | Supabase (Postgres) *or* Neon Postgres + Prisma ORM | Managed, cheap, scales |
| Auth | Auth.js (NextAuth) — credentials/magic links | Flexible, Next.js native. Clerk = faster alternative |
| File storage | Cloudflare R2 / S3 | Property & maintenance photos |
| Email | Resend | Transactional notifications |
| Payments (Phase 2) | GCash | Rent collection (send-money + reference flow), receipts |
| Deploy | Vercel + Supabase/Neon | Zero-config |

## Architecture

- **Route groups:** `(marketing)` landing/auth · `(dashboard)` landlord app (protected) · `(tenant)` tenant portal (protected)
- **Data access:** Server Components + Server Actions (or tRPC if you prefer explicit APIs)
- **Multi-tenancy:** every table scoped by `userId`/`orgId`; enforce scoping in every query (use RLS if Supabase)
- **Roles:** `users.role` — `landlord` (dashboard) / `tenant` (portal); the session callback exposes it, login routes by it, and both layouts guard in opposite directions

## Data Model (Prisma sketch)

- **User** — landlord account (email, hashed password, plan)
- **Property** — address, type, photos, units[]
- **Unit** — propertyId, name/number, bedrooms, rentAmount, status (vacant/occupied)
- **Tenant** — name, phone, email
- **Lease** — unitId, tenantId, start/end dates, rent, deposit, status
- **Payment** — leaseId, amount, date, method, type (rent/late fee)
- **Expense** — propertyId, category, amount, date, vendor
- **MaintenanceRequest** — unitId, tenantId, title, description, priority, status (new → in progress → resolved), photos
- **Document** — leases, inspection reports
- **Notification** — in-app + email log

## MVP Feature Set (Phase 1)

1. Auth: register/login, email verification
2. Dashboard KPIs: occupancy rate, income this month, open requests, expiring leases
3. Properties & units: CRUD with photo uploads
4. Tenants & leases: CRUD, lease-end alerts
5. Finance: record payments & expenses, recurring rent, simple P&L per property
6. Maintenance: create/update requests, status workflow, photos
7. Email notifications (new request, rent due, lease expiring)

## Phase 3

- **PWA / mobile-first polish** ✅ — installable to the home screen: `app/manifest.ts` (standalone display, `start_url: /dashboard` so the launcher role-routes like the app does, emerald `theme_color`, Dashboard/Finance/Maintenance app shortcuts, PNG icons at 192/512 plus a full-bleed **maskable** variant rasterized from the SVG logo), a deliberately conservative `public/sw.js` (never touches `/api` or non-GET; navigations are network-first with a branded `public/offline.html` fallback and HTML is never cached; hashed `/_next/static` + icons are cache-first), an install prompt that uses the native `beforeinstallprompt` sheet on Chromium and spells out Share → Add to Home Screen on iOS (dismissal persists in localStorage), and mobile polish: `viewport-fit=cover` with `env(safe-area-inset-*)` padding on both app headers, the drawer and the sidebar footer, `overscroll-contain` on the drawer, and `nosniff`/`DENY`/referrer headers plus `no-store` + CSP on `sw.js`. The SW registers **in production only** so dev HMR stays honest.
- **Tenant-reported media (photos + video)** ✅ — the portal's "Report an issue" form takes up to **3 files** (images plus short MP4/MOV/WebM clips), previewed as thumbnails with per-file size and a remove button before sending. Photos are **re-encoded in the browser** (`src/lib/media-client.ts`: 1600px long edge, JPEG q0.82) because a modern phone photo is 3–5MB while a serverless request body caps out around 4.5MB — an 18MB test photo lands at 901KB, so three photos and a clip fit comfortably. Files land in `documents` through the new nullable `maintenance_request_id` and show as thumbnails on the tenant's portal list **and** in the landlord's Maintenance row. The documents route now serves images **inline** (so they can be thumbnails) with `?download=1` forcing an attachment, keeps everything else as a download, and grants the reporting tenant access to their own uploads even after their lease has ended; a failed attachment never swallows the report. Real video volumes still need R2/S3 — the honest limit today is short clips
- **Lease notes + attachments** ✅ — every lease page now carries free-text **Notes** (new `lease_notes` table: author, timestamp, author-only delete, 2000-char cap) and **Attachments** using the previously-unused `documents` table, now carrying a `data` column. Files are stored **in Postgres as base64** rather than written to `public/`, because Vercel's filesystem is read-only at runtime — anything written there would vanish on redeploy, and object storage (R2/S3) is still parked for lack of credentials. Downloads go through `/api/documents/{id}`, which re-checks lease/unit/property access before streaming and always serves `Content-Disposition: attachment` (never inline, so an uploaded file can never execute in the app's origin). Uploads are **allowlisted** by MIME type (PDF, images, Word/Excel/text — HTML and SVG deliberately excluded), capped at 5 MB with `serverActions.bodySizeLimit` raised to 8 MB for multipart overhead, and filenames are sanitised before storage and again in the download header. Moving to R2 later only means nulling `data` and putting a key in `url`
- **Lease signing (no vendor)** ✅ — both parties sign in-app, so a lease can be executed without DocuSign/Dropbox Sign: `lease_signatures` table (one row per party per lease, unique on lease+role, so re-signing replaces), a **Signatures** card on the lease edit page and in the tenant portal, and a shared `SignatureDialog` where a party either types a name (rendered in a local script font — no web font needed) or draws a mark on a pointer/touch canvas stored as a PNG data URL (400KB cap). Both paths require an explicit electronic-signature attestation, which is what makes either one binding; the checkbox is controlled because React clears uncontrolled fields when a form action settles. `/leases/{id}/signed` renders a print/PDF-ready copy with both signatures, dates and methods. Landlord-side and tenant-side actions are separate (`signLeaseAction` gated by `canManageUnit`, `signLeaseAsTenantAction` scoped to the tenant's own lease) but share `src/lib/signatures.ts`. DocuSign/Hellosign can slot in later by adding provider/envelope columns without changing the UX; tenant screening still needs credentials
- E-sign vendor (DocuSign/Dropbox Sign) + tenant screening — parked until credentials exist
- QuickBooks/Xero integration — parked (needs an OAuth app)
- **Forgot / reset password** ✅ — `/forgot-password` (linked from the sign-in card) emails a one-time link; `/reset-password?token=…` sets the new one. `password_reset_tokens` stores **only the SHA-256 hash** of a 32-byte token, so a leaked DB row or backup can't be replayed into a working link; tokens are single-use and expire after 60 minutes. The request action **always** returns the same confirmation whether or not the address is registered — a different reply for unknown addresses would turn the form into an account-enumeration oracle — and a 10-minute resend cooldown (keyed on the newest *unused* token, since minting one deletes the previous) silently absorbs repeat requests. A reset stamps `users.password_changed_at` and the `jwt` callback returns `null` for tokens minted before it, signing other devices out: that is the only hook that works, because server-side `auth()` re-attaches the token as `session.user` and a session callback cannot remove it (cost: one indexed `users` lookup per session read). `session.maxAge` is now an explicit 7 days. Tenant accounts use the same flow and land on `/portal` afterwards
- **AI: expense categorisation + rent suggestions** ✅ (built against the "LLM seam + honest fallback" pattern — `src/lib/ai.ts` makes one OpenAI-compatible `chat/completions` call over plain `fetch`, so no SDK is needed and `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` switch providers; with no key every helper returns null and the callers fall back to deterministic rules)
  - **Expense categorisation** (`src/lib/expense-intelligence.ts`) in the expense dialog, debounced as the vendor/notes are typed. Order of trust: **the landlord's own history for that vendor** (repeat bills are the common case and their bookkeeping beats any guess — "You filed 3 of 3 past Meralco expenses as this"), then the model, then vendor/keywords. A category the user picks themselves always wins over a suggestion, and with no signal at all nothing is shown rather than a weak guess.
  - **Rent suggestions** (`src/lib/rent-insights.ts`) on the unit dialog: comparable units in the same property (falling back to the city), **occupancy-weighted median** — occupied units count double, since that is a rent the market has actually accepted — plus a 25th/75th percentile range, rounded to ₱500. It never claims market data it doesn't have; the reasons line says exactly what it looked at. With a model configured the same comparables are handed over for judgement, **clamped to ±60% of the computed median** so a hallucinated number can't escape into the UI.
  - Both chips are explicitly badged **AI** or **RULES** so a rule-based guess is never passed off as AI. Access is checked in SQL (a crafted unit id can't pull another landlord's comparables). Enabling the model = adding `AI_API_KEY` (+ optionally `AI_BASE_URL`/`AI_MODEL`) to `.env.local`/Vercel; nothing else changes.
- **Email OTP at registration** ✅ — `/register` collects name/email/password, then asks for a 6-digit code before the account exists. The signup is held in **`pending_registrations`** (`src/lib/email-verification.ts`) and only becomes a `users` row when the code comes back, so an unverified address never holds a usable login and abandoned signups can't lock an address out (rows expire and are purged). Codes are 6 digits, expire after 15 minutes, allow **5 wrong guesses** (the 5th destroys the row and forces a fresh request), and are stored as an **HMAC-SHA256 keyed with `AUTH_SECRET` over `email:code`** — a bare hash of six digits falls to an offline sweep of a million values, and binding the address stops a code being replayed against another signup. The pending row is claimed with `delete … where code_hash = … returning`, so two parallel submissions can't both spend the same code. A 60-second cooldown on both starting and resending keeps the form from being used as a mail cannon; `/api/auth/resend-code` answers **identically** for an address with no signup waiting, so it can't be used to test who has an account. The verified user is created with `email_verified` already set (the address *was* proven), and sign-in is unchanged — tenants created by landlords never see this. A wrong code keeps you on the form; a burned or expired one drops back to the details step to start over.

### Dev-environment gotchas (learned the hard way)

- **CSS/theme edits need `rm -rf .next` + a dev-server restart.** The custom `turbopack.rules` entry for `*.css` in `next.config.ts` caches the compiled stylesheet, so Turbopack keeps serving the old chunk (same filename hash) even after a full restart — theme changes look like they simply didn't happen. Clear `.next` after touching `globals.css`.
- The Next dev indicator defaults to **bottom-left**, where it sits on top of the sidebar footer's theme toggle and sign-out button and swallows clicks. `devIndicators.position` is set to `"bottom-right"` in `next.config.ts`.
- Playwright: `button[aria-label="…"]` matches three toggles across desktop sidebar / mobile header / drawer — scope with `:visible` or a container locator, or clicks hit hidden elements.
- Never edit markdown with PowerShell `Get-Content`/`Set-Content` round-trips — it mangles em dashes into U+FFFD. Use the edit tool or Node (`fs.readFileSync/writeFileSync` with `\uXXXX` escapes).
- **A long-running dev server can hold a stale module graph after `src/db/schema.ts` gains a new table** — a new module importing it gets `undefined` instead of the export, surfacing as `Cannot read properties of undefined (reading '<column>')` in a route handler. Restart `next dev` after adding a schema table; no `.next` wipe needed.
- **`AUTH_URL` is the host every link inside an email is built from**, and `.env.local` and the Vercel project need *different* values (`http://localhost:3000` vs the deployment URL). A stale one makes sending look broken while it silently works. **Settings → Email delivery** shows the configured sender + link target, sends a real test message and reports the provider's verdict, and warns when `AUTH_URL`'s host doesn't match the site being viewed. Two more traps it surfaces: `example.com` recipients are rejected by Resend in all environments, and the shared `onboarding@resend.dev` sender only delivers to the address on the Resend account — so **test addresses are `logo-demo@example.com` (never receives) and a real mailbox (always receives)**.
- The password-reset resend cooldown is silent *by design* (enumeration), so a retry inside 10 minutes sends nothing while still saying "check your inbox" — it logs `[password-reset] request suppressed by the resend cooldown` instead. A throttle that hides itself like this reads as a broken feature; check the server log before assuming mail is failing.
